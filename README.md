# Office Buddy

A German Windows desktop app that makes everyday PDF and image tasks simple for people who are not computer experts. It opens on a start screen with eight large tiles, one per task. Everything runs on the PC itself: nothing is uploaded, and the app never goes online.

| Tile | What it does |
|---|---|
| **Zusammenfügen** | Combine several PDFs into one, in the order you drag them into |
| **Seiten bearbeiten** | Rotate, reorder and remove Pages; blank backs of duplex scans are found automatically |
| **Seiten herauslösen** | Save selected Pages as a new PDF |
| **Aufteilen** | Split a PDF into several Parts |
| **Verkleinern** | Make a PDF small enough to send by email (under 10 MB), or split it into email-sized Parts |
| **Bilder zu PDF** | Turn phone photos and other JPG/PNG images into one PDF, one A4 Page each, the right way up |
| **PDF als Bild** | Save Pages as JPG images |
| **Bildgröße ändern** | Make a photo or other JPG/PNG image smaller or bigger, by percentage or by width and height in pixels |

Every change can be undone until the result is saved, and saving always asks where to put the file, suggesting a sensible name next to the original.

## Getting it onto a PC

Build a single `OfficeBuddy.exe` that runs without installing:

```
dotnet publish src\OfficeBuddy.App -c Release -o artifacts\single -p:PublishSingleFile=true -p:IncludeAllContentForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:DebugType=none
```

`artifacts\single\OfficeBuddy.exe` contains everything the app needs, so nothing else has to be installed. Copy it to the PC and put a shortcut on the desktop; to update, replace the exe with a newer one. It unpacks itself into a temporary folder on its first start, which takes a few seconds; later starts are quick.

## Development

Needs Windows 10 (2004) or later and the .NET 10 SDK.

```
dotnet build                                   # everything
dotnet run --project src\OfficeBuddy.App       # start the app
dotnet test                                    # all tests
```

The solution is [OfficeBuddy.slnx](OfficeBuddy.slnx):

- **[src/OfficeBuddy.Core](src/OfficeBuddy.Core)** – all PDF and image logic. Each tile has a *session* (for example `CompressSession`) that holds the complete state of its screen, with undo/redo, and saves the result.
- **[src/OfficeBuddy.App](src/OfficeBuddy.App)** – the WinUI 3 screens. They stay thin and call the sessions. All German texts are in [Strings/de-DE/Resources.resw](src/OfficeBuddy.App/Strings/de-DE/Resources.resw), the blue look in [Themes/Blue.xaml](src/OfficeBuddy.App/Themes/Blue.xaml).
- **[tests/OfficeBuddy.Core.Tests](tests/OfficeBuddy.Core.Tests)** – xUnit tests that act like a user through the sessions and check the files written. Sample PDFs and images are generated by the tests themselves.
- **[third_party/Ghostscript](third_party/Ghostscript)** – the bundled Ghostscript that Compress uses.

The screens are not tested automatically; check them by hand.

### Libraries

- [PDFsharp](https://www.pdfsharp.com/) 6.2 (MIT) builds the PDFs. Stay on 6.2: from 6.5 on it is AGPL with a licence check.
- `Windows.Data.Pdf`, built into Windows, draws Pages for thumbnails, the preview, Page to image and blank-page detection.
- [Ghostscript](https://ghostscript.com/) 10.06 (AGPL), run as a separate program, compresses PDFs.
- [PdfPig](https://github.com/UglyToad/PdfPig) reads PDFs back in the tests.
